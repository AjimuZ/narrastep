# Narrastep guide for Claude Code

<!-- markdownlint-disable MD029 -- rules are numbered continuously so they can be cited. -->

Claude Code and every contributor working in this repository must follow these rules.

## Before editing

1. Read `README.md`, `docs/STATUS.md`, `docs/ROADMAP.md` and the documents relevant to the change.
2. Follow the `ajimu-conventions` skill for every change and `ajimu-pixel-ui` for any interface
   work. The skills live in the local, Git-ignored `.claude/skills/`; this file and the documents
   in `docs/` restate every rule that matters, so they also apply when the skills are absent.

## Code and language

3. Keep source code, names, comments, docstrings, errors, configuration, API descriptions and
   documentation in English. The interface is bilingual: every user-visible text has an English
   and an Italian translation in the same change ([ADR 0015](docs/decisions/0015-english-and-italian-interface.md)).
   Preserve transcript text in its spoken language.
4. Prefer pragmatic, business-readable changes that fit the current boundaries. Avoid speculative
   abstractions and unrelated refactors.
5. Start every module with a one-line responsibility statement and give every function a concise
   contract comment or docstring: what it returns, requires and how it fails. Add internal
   comments only for business rules, non-obvious dependencies, workarounds or risks.

## Documentation

6. Update documentation in the same change as behavior: `docs/API.md` and `docs/openapi.json` for
   endpoints, `docs/ARCHITECTURE.md` for boundaries, `docs/PROCESSING_PIPELINE.md` for
   algorithms, `docs/UI.md` for screens.
7. Update the roadmap item, `docs/STATUS.md` and, for user-visible changes, `CHANGELOG.md`. Check a
   roadmap item only when its exit checks passed, and add dated evidence.
8. Record material decisions as ADRs under `docs/decisions/` and list them in `docs/README.md`.
9. Never present planned behavior, sample data or an unexecuted check as real.

## Verification

10. Run the formatting, lint, type, test, build and documentation checks relevant to the change
    (see `docs/DEVELOPMENT.md`). Never claim a command or feature works without verifying it.

## Product constraints

11. Never add telemetry, analytics, cloud storage, remote transcription or inference, required CDN
    assets or hidden network requests.
12. Never weaken local-first storage or privacy guarantees without an accepted ADR.
13. Never require the user to install software on the computer. Docker is required; the desktop
    window uses the host Node.js and npm already present and keeps Electron inside `desktop/`.
    Every other runtime dependency runs in a container.
14. Keep optional heavy features (such as the local generation model) out of the default
    installation; the user installs them from the interface, and a setting can disable them.
15. Treat SQLite and the local project workspace as persistent truth. Redis is temporary
    coordination infrastructure.
16. Use safe subprocess argument arrays, validate all media with FFprobe, keep user paths below
    configured roots, and never expose stack traces or sensitive transcript text in normal logs.
17. Use only free, open-source-compatible licenses and no paid services or certificates in what the
    project depends on. The owner's personal development tools, such as the plan behind Claude Code,
    are not dependencies: nobody needs them to build, run or contribute. The project is public and
    non-commercial. Record every new dependency in `docs/LICENSES.md`.

## Commits

18. Write a concise English imperative subject describing the resulting behavior. Never mention AI,
    assistants or automated authorship, and never add `Co-Authored-By` or "generated by" trailers.
    When the local skill is present, validate with
    `python .claude/skills/ajimu-conventions/scripts/check_commit_message.py .git/COMMIT_EDITMSG`.
    Never commit `.claude/` or `skills-lock.json`.
19. Commit, push or publish only when the owner asks. Starting the runner is asking it to commit
    and push verified tasks on `main`, never with force. Never bypass hooks or change Git
    configuration.

## Autonomous runner

20. `scripts/ralph/` runs one fresh Claude Code process per task
    ([guide](scripts/ralph/README.md)). In such a session `scripts/ralph/CLAUDE.md` applies too: the
    runner verifies and commits, and the agent never commits or edits the task state. Add a task to
    `scripts/ralph/prd.json` whenever a roadmap item is added.
