## Codebase Patterns
- A commit message may not name authoring tools, even as a file: write "the contributor guide", not the file name of the root guide, or the commit is rejected and the attempt is lost.
- Git on Windows does not record the executable bit, and sessions cannot set it. A new script that must run as ./name needs it: name that file in the summary so the owner's session can set it, because a test checking the mode fails once the file is tracked.
- In your structured output, `conventions_ack` must hold only the 16 hexadecimal characters after `ACK-TOKEN: `, without that label. With the label the whole attempt is rejected, however good the work is.
- The owner's computer has Docker and the runner runs there. Older notes saying a check could not run because a worker had no Docker are history; run those checks now.
- Host Python (3.15) and Node.js (24) differ from the project's (3.14.10 and 22.23.1): run project commands through scripts/ralph/sandbox.sh.
- Baseline on 2026-10-30, in the sandbox: 281 backend passed and 17 opt-in skipped, 183 frontend, 127 desktop, 408 Playwright; `check.sh stack` builds every image and reports health ok in about 2.5 minutes.
- Next free ADR number after the setup: 0020. ADR 0017 (Valkey) and 0018 (source video removal) exist on main.
- The sandbox cannot reach ports published on the host; to talk to the isolated stack, use `./scripts/ralph/stack.sh exec -T api ...`.
- Other projects share Docker's 8 GB. `ENOMEM` or a refused connection in a browser run means load, not a defect; the checks repeat by themselves.
- The broker is Valkey 9.1.3 under the Compose service name `redis`, with the `narrastep-redis` volume: the name is kept on purpose (ADR 0017).
- `./scripts/ralph/stack.sh exec -T api python scripts/full_job_check.py --api http://127.0.0.1:8000/api/v1` proves a running stack end to end in seconds with the tiny model.
- `check.sh stack` can reuse cached layers; use `stack.sh build --no-cache` when a check must really run in the image build.
- Run one Playwright command at a time in the sandbox: parallel runs share the dev server on port 4200, and when one ends the other fails with ERR_CONNECTION_REFUSED.
- Declare health checks in `docker-compose.yml`, not in a Dockerfile `HEALTHCHECK`, because Podman's default OCI image format drops it; `backend/tests/test_container_images.py` enforces this.
- Name images built from this repository `localhost/<name>:<version>` and pulled images with their full registry path, keeping tag and digest; `backend/tests/test_container_images.py` enforces this.
- When a version appears in tests as both the pin and an 'older installed' value, bump only the pin and keep the older value older.
- When a stub-tested handler changes behavior, grep the opt-in real-runtime harness for the same call, because a prompt that now waits for input can hang it.
- Inject platform-dependent behaviour (such as process.platform) into the pure function and cover every platform with stand-ins. Keep a real run on the target system as a named owner check, never as a claim.
- Where the page has no bridge to the shell, derive the host from the user agent rather than adding a preload or IPC channel; this leaves the isolation rules untouched.
- Scripts that run from stdin inside a container must not touch `__file__` at import. Resolve repository paths lazily, in the code path that needs them.
- Keep a container-inventory script as a pure compare function plus a thin engine call. Test the compare function with fixed listings and edited copies of the document, and test the stdin path with a subprocess.
- Write host-probing shell scripts as pure profile functions plus probes. Let a NARRASTEP_PROBE_* variable (set but empty means unknown) replace each probe, so tests fix the hardware without root or fake /proc files.
- Prove that a script calls no network tool by putting failing stubs for curl, wget, nc and similar commands on PATH while it probes the real machine. Add a scan of the script text with comments removed.
- Pin external model files in a frozen-dataclass catalog with revision, name, size and 64-hex SHA-256, and test the shape (40-hex revision, 64-hex hashes, bare file names, totals against the docs) so a pin can only change together with its documentation.
- Keep a persisted lifecycle as a StrEnum, a dict of allowed transitions and one `transition_*` function that validates, writes and commits; a missing row means the initial state. Test the edge set against the documented diagram and add a parametrized table of refused transitions.
- Test that every setting key appears in docker-compose.yml with the same default as the Settings class and in the README and spec, so documentation and Compose cannot drift.
- Generate a config file to a temporary name in the target directory and mv it into place only on success, so a failed run leaves nothing a later run would treat as existing.
- Test shell scripts in a temporary copy of the project with stub tools on a restricted PATH, so tests never touch the owner's real files.
- Background work that needs the Internet runs in a daemon thread of the API process (the only service on the `local` network), with a stop control, a registry and a startup resume hook, never in the Celery worker.
- Tests that need HTTP use a local `ThreadingHTTPServer` with scripted behaviors and a monkeypatched module-level base URL. No production setting or request can change that URL.
- Redirects are checked in a custom `HTTPRedirectHandler`, so the host allowlist applies to every hop and the `Range` header survives.
- Check order in model state actions: known model (404), then kill switch where it applies (403), then state (409), then side effects. Do the destructive file removal before the state change.
- Run ruff format after editing and export_openapi.py after changing routes, then check.sh backend.
- Stub-test start scripts with a restricted PATH (fake binaries plus symlinks to a few system tools) and a fake uname to exercise platform branches.
- Reuse the existing background-worker, progress and cancel machinery by passing a strategy callable, rather than copying the download loop for a second source.
- A file selected by catalog name under a fixed root, refusing links and non-regular files, is how to read user-supplied files without taking any path from a request.
- Read .env values in start scripts with shell built-ins (read, case, parameter expansion) so they work on the restricted PATH used by script tests.
- Avoid names such as secret, token or password in test code, even for harmless sample strings.
- Keep new generation logic as pure functions with explicit budget parameters, and log counts only, never transcript or notes text.
